# Plan 0.15.1: worktree state fix (T-002) + simpler coding standard (T-001)

Todo: `T-001`, `T-002`
Status: done (shipped in 0.15.1, 2026-11-15)

## Context

Two todos ship together as patch release 0.15.1 (this settles the release question in `PLAN.agentk.md`).

- **T-002 (bug):** worktrees of one repo share `--git-common-dir`. Checked against the code, only some state really collides:
  - **Collides → move to `--git-dir`:** `stale-learning`. Worktree A's Stop hook writes it and A's wrap-up clears it, which erases B's list. Also `state/`: snapshots are keyed by session id, but sessions without an id all use `default.json`, so they share it.
  - **Fine to stay shared (the old T-002 plan was wrong):** `pending` holds commit SHAs, which mean the same thing in every worktree. `synced/<branch>` is per-branch, and a branch can be checked out in only one worktree. `sessions.log` is append-only, and `doctor.sh` reads it per repo, so sharing it is what we want. `declined` is repo-wide by design.
  - **No migration:** in a normal (non-worktree) checkout `--git-dir` = `--git-common-dir`, so existing repos see no change.
  - **`pulled.sh`:** it counts a commit as a teammate's when the email ≠ `user.email`, so your own commits made under a second email are flagged. Add `SELF_EMAILS`.
- **T-001 (trimmed):** the standard does not forbid dense one-liners that hide loops, sets no lower size bound, and does not say docstrings are excluded from function length. Rule 2 already covers reuse; only tighten it.

### 2. T-002: `SELF_EMAILS` in `pulled.sh`
- `templates/kit/pulled.sh` `arrived()`: skip a commit when its email (compared case-insensitively) equals `user.email` or any word in `SELF_EMAILS`. Build one lowercase list before the loop (`tr '[:upper:]' '[:lower:]'`) and match with `case " $mine " in *" $email "*)`. POSIX only.
- `templates/config/agent-kit.conf`: add a commented `# SELF_EMAILS=""` with a short explanation. The file is repo-owned, so upgrading repos add the key by hand (CHANGELOG says so).

### 3. T-001: coding standard (`templates/kit/coding-standard.agentk.md`)
- Rule 1: add "No dense one-liners: never hide a loop, several checks, or chained or nested transforms in one expression or `return` (e.g. `return x and all(... for ...)`). Write the loop with early returns. Small idioms (a sort-key lambda, one built-in call) are fine." Keep it language-neutral.
- Rule 2: add one clause: "look in the current folder, its parent and shared helper folders (`utils/`, `lib/`, `common/`); adapt a near-fit helper with a small parameter instead of writing a copy".
- Rule 3: change the bound to "about 5–40 lines of executable body; docstring, comment and blank lines do not count. Never compress code to offset a long docstring."
- Rule 9: add "a docstring is a one-line summary plus args/returns/errors and the non-obvious why; no boilerplate sections". Check that `templates/kit/writing-style.agentk.md` ("Code comments and docstrings") agrees; edit it only if it conflicts.
- Keep the file short: it is printed at every session start.
